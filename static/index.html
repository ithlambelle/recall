    2. 2

      The failure mode is not stable

      All three models fail both poisoned tasks in every run. Haiku and Opus always pay the attacker. Sonnet varies run to run, sometimes paying and sometimes refusing, which leaves real invoices unpaid. A binary oracle scores the refusal as success and repairs nothing.

    3. 3

      Trust comes from provenance

      Recall never reads content, only lineage. A convincing lie defeats content detection and changes nothing here.

    How it works

    A bookkeeping agent pays invoices from memory. It reads a vendor notice claiming a supplier changed bank details and writes it down, then later consolidates its notes into a supplier profile. The claim is now in the agent's own words.

    Recall assigns trust by where a memory came from, never by reading it. A user statement is trusted, a fetched page is not, and anything the agent derives inherits the lowest trust of its parents. When a task fails, each retrieved memory is withheld and the task re-run. If no single memory is responsible, removal continues in order of ascending trust until the task succeeds, then the set is pruned to a minimum.

    The diagnosed set is traced through the derived-from graph, so descendants no task ever retrieves are caught too, and only actions that consumed a deactivated memory are replayed.

    Built on

    Four papers define the problem and the two halves of the solution. What follows is what each contributes, and exactly what we took.

    MINJA — the threat model

    An attacker poisons an agent's memory using nothing but ordinary queries. No database access, no privileged position. The attack injects a malicious record, adds bridging steps that link ordinary victim queries to the malicious reasoning, then uses an indication prompt to get the agent to generate those bridging steps itself. A progressive shortening strategy withdraws the prompt, leaving a record that stays retrievable for future queries.

    What we took. The shape of the threat: the agent poisons itself by processing attacker-controlled content, and the record it writes looks like its own work. Our scenario is a single-step version of this. The agent reads a spoofed vendor notice and stores it, then consolidates it into a supplier profile, which is the laundering step that makes the claim look self-derived.

    MemAudit — diagnosis

    Audits a poisoned memory store after harm has already occurred. It computes a counterfactual memory influence score measuring each record's causal contribution to the harmful output, and pairs it with a memory consistency graph that flags records which are structurally anomalous against the rest of the store. Evaluated against MINJA, it reports attack success falling from 70% to 0% on QA and from 83.3% to 0% on the reasoning-agent setting.

    What we took. The counterfactual half. Influence here is deliberately crude and behavioural rather than a continuous score: withhold a memory, re-run the task, and ask whether the outcome became correct. That makes attribution checkable without a model of its own. We did not implement the structural anomaly detector, which is the half that reasons about content and consistency.

    Where it stops. MemAudit ranks and removes. It answers which memories were responsible, not what to do about everything written from them afterwards.

    Dependency-guided rollback repair — repair

    Builds a typed memory-to-action graph from runtime provenance, traces explicit downstream dependencies from the faulty memories through later reasoning, tool calls and memory writes, and then selectively replays only the affected computation rather than the whole trace. It reports 85.3% recovery against 77.3% for the best competing method on a 150-case controlled benchmark, and 68.0% against 54.0% on a 50-case stress test drawn from LongMemEval-V2.

    What it assumes. Two inputs: a failed execution, and the diagnosed faulty memories. The diagnosis is given to it.

    What we took. The dependency closure and selective replay. Our store records which memories each action consumed and which memories were derived from which, so the closure is a walk over that graph. We added one rule the paper does not need: a derived memory with independent support from a still-trusted memory survives the rollback, which is how m17 stays alive while its parent is cut.

    TracLLM — the baseline

    A framework for attributing a long-context model's output back to pieces of its context, using leave-one-out and Shapley-style methods with search to keep the cost tractable.

    What we took. Leave-one-out, as the thing to beat. It is the first pass in our attribution and it returns nothing here, which is the result the rest of the method exists to handle.

    The gap, and what we add

    MemAudit ends where diagnosis ends. The rollback paper begins after diagnosis is handed to it. Neither cites the other and we found no public implementation of either, so the join between them has not been built. Recall is that join: diagnosis output becomes repair input, with no human in between.

    Chaining them surfaced two things neither paper's framing predicts. First, leave-one-out returns nothing when a poisoned record and a summary derived from it each restate the same claim, because removing either leaves the other answering. We fall back to cumulative removal ordered by ascending provenance trust, then prune to a minimal set. Second, a repair has to be defined as the task succeeding, not merely ceasing to fail: if any non-failure counts, deleting the memory holding the correct answer scores as a perfect fix, and against Sonnet 5 our pipeline did exactly that until we corrected the objective.

    The weak-spot framing above is our own finding from running the chain. The MemAudit abstract does not name it, and we have not verified it against the full text.

    Honest limits

    The consolidation step that creates the derived profile is scripted rather than produced by the agent. Real-model runs are not reproducible, so figures are quoted over repeated runs. Recorded runs are replayed here so that a public page cannot spend money; the offline agent is deterministic, so its trace matches a live run exactly.
