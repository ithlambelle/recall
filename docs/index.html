    How it works

    A bookkeeping agent pays invoices from memory. It reads a vendor notice claiming a supplier changed bank details and writes it down, then later consolidates its notes into a supplier profile. The claim is now in the agent's own words.

    Recall assigns trust by where a memory came from, never by reading it. A user statement is trusted, a fetched page is not, and anything the agent derives inherits the lowest trust of its parents. When a task fails, each retrieved memory is withheld and the task re-run. If no single memory is responsible, removal continues in order of ascending trust until the task succeeds, then the set is pruned to a minimum.

    The diagnosed set is traced through the derived-from graph, so descendants no task ever retrieves are caught too, and only actions that consumed a deactivated memory are replayed.

    Built on

    MINJA supplies the threat model. MemAudit supplies counterfactual diagnosis and names mutually reinforcing memories as its weak spot, which is exactly the case here. Dependency-guided rollback repair supplies the repair but assumes diagnosis is given. TracLLM is the leave-one-out baseline. We found no public implementation of the middle two, and nothing joining them.

    Honest limits

    The consolidation step that creates the derived profile is scripted rather than produced by the agent. Real-model runs are not reproducible, so figures are quoted over repeated runs. Recorded runs are replayed here so that a public page cannot spend money; the offline agent is deterministic, so its trace matches a live run exactly.
