Recall

An agent believed a lie. Find it, and everything it grew into.

Causal diagnosis + dependency-guided rollback Verified on Haiku 4.5 · Sonnet 5 · Opus 5 9/9 runs repaired

Find the memories that actually caused an agent's harmful action, roll back everything derived from them, and replay only what that touched.

What this is

An agent believed a lie, and deleting the lie isn't enough

AI agents are starting to keep persistent memory — notes they write to themselves and read back later. That memory is mostly invisible. You can't see what was written, where it came from, or how to undo it. So if something false gets in, it stays in, and it quietly shapes every decision the agent makes afterwards.

1 · THE LIE GETS IN

The agent reads a fake page

A bookkeeping agent pays invoices. It reads a web page claiming a supplier changed bank details, and writes that down. The page is fake — this is ordinary invoice fraud, aimed at the agent instead of a person.

2 · THE LIE SPREADS

It gets tidied into a “fact”

Later the agent summarises its notes into a clean supplier profile. The lie is now restated in the agent's own words, and it looks like something the agent worked out rather than something it read off a web page.

3 · CLEANUP FAILS

Deleting the page doesn't help

Delete the fake page and the summary still says the same thing, so the money still goes to the attacker. Wipe all memory instead and the agent is safe but useless — it no longer knows how to pay anyone.

4 · WHAT RECALL DOES

Cut the branch, keep the tree

Recall re-runs the task with each memory withheld to find which ones actually caused the payment, follows the trail to everything written from them, switches off just that branch, and redoes only the payments that relied on it.

The one idea. Recall never tries to judge whether a memory looks suspicious — a convincing lie beats that every time. It scores memories by where they came from. You said it yourself: trusted. A web page said it: not trusted. And anything the agent writes from an untrusted memory inherits that distrust, so a lie cannot be laundered into a fact by being summarised.

Prior work

Four papers, and the gap between two of them

MINJA — Memory Injection Attacks on LLM Agents via Query-Only Interaction

arXiv:2503.03704

Shows an attacker can poison an agent's memory using nothing but ordinary queries — no access to the database, no privileged position.

Used as our threat model. The scenario here is a MINJA-style write: the agent poisons itself by reading attacker-controlled content.

MemAudit — Post-hoc Auditing of Poisoned Agent Memory via Causal Attribution and Structural Anomaly Detection

arXiv:2605.23723

Audits agent memory after the fact by removing memories and re-running to see which ones actually changed the outcome. Names mutually reinforcing poisoned memories as its weak spot, and ranks and removes — it does not repair.

We implement the diagnosis half, and hit exactly the weak spot the paper names: see the leave-one-out sweep below return nothing.

From Faulty Memories to Corrected Actions: Dependency-Guided Rollback Repair for Memory-Augmented Agents

arXiv:2608.10502

Given a set of bad memories, walks a provenance graph to undo everything derived from them and replay the affected actions. Assumes the diagnosis is already given.

We implement the repair half, including preserving derived memories that have independent trusted support.

TracLLM: A Generic Framework for Attributing Long Context LLMs

arXiv:2506.04202

Leave-one-out and Shapley methods for attributing an LLM's output to pieces of its context.

Our leave-one-out baseline — the thing that provably fails here.

The gap

MemAudit ends where diagnosis ends. The rollback paper begins after diagnosis is handed to it. Nobody joins them, and we could not find a public implementation of either. Recall is that join: diagnosis feeds repair, end to end, on one system.

What's new here

Contributions, and what they cost

ContributionWhy it matters
Chaining diagnosis to repair Two papers, one pipeline. Diagnosis output becomes the rollback input, with no human in between.
A fallback for reinforcing memories Leave-one-out returns nothing when a lie and its summary each restate the other. We fall back to cumulative removal ordered by provenance trust, then prune to a minimal set. This is MemAudit's stated weak spot.
Provenance-scored writes with taint Trust comes from source, never content, and derived memories inherit the minimum trust of their parents. A convincing lie is scored the same as a clumsy one.
A five-way outcome taxonomy Distinguishes a refusal that protected the user from one that just failed the task, and never scores an unreadable reply as safety. Both distinctions changed our results.
Repair defined as task success Requiring the outcome to be correct, not merely not failing, stops the system from “fixing” things by deleting the memory holding the right answer.

A plain harmful/not-harmful oracle would have scored Sonnet's failure as a success and repaired nothing at all.
recall — audit replay
Builds on MemAudit (arXiv:2605.23723) for counterfactual influence and dependency-guided rollback repair (arXiv:2608.10502); threat model from MINJA (arXiv:2503.03704). We could not find public implementations of the first two — Recall chains them, feeding MemAudit-style diagnosis into a rollback step that assumes diagnosis is already given.
Ground truth is used only to colour the known poison annotation; the pipeline never reads it.
